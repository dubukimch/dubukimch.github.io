BEFORE YOU START

시작하기 전에

  • Assistant Host와 Python 서비스가 실행 중이어야 합니다.
  • 실행 터미널의 일회성 Client key를 준비합니다. 매뉴얼이나 내보내기에 키를 적지 않습니다.
  • PLC 상태 실습은 PLC Simulation :5180 실행과 machine-03의 매핑이 필요합니다.
  • Assistant 대화 내보내기 예시 ↓

PLC HTTP 조회와 결정적 Fake 답변을 사용하는 로컬 읽기 전용 실습. History, Gateway, DataCatalog, OEE는 Mock 구성이다.

01

비서 접속과 조회 범위 확인

실행 확인

역할·자산·소스를 정한 뒤 로컬 Host를 확인합니다.

  1. 현재 실행 키 입력

    Client key: 현재 터미널 키

  2. 역할과 자산 지정

    통합 비서·machine-03

  3. 소스 설정 확인

    PLC_Simulation·TwinForge

  4. Host 응답 확인

    Host 확인 → HTTP·시각

결과 확인

Host 응답 시각과 HTTP 코드가 표시됩니다. 소스 선언과 개별 조회 성공은 별개입니다.

401이면 현재 실행의 Client key를 확인합니다. 키는 문서나 공유 자료에 넣지 않습니다.

전체 조작 단계와 문제 해결

접속과 조회 범위 확인

선택한 역할과 자산, 실제 소스 구성을 확인합니다.

  1. 채팅 주소를 열고 Client key에 실행 터미널의 키를 입력합니다.
  2. 비서 역할을 통합 비서, 논리 자산 ID를 machine-03으로 둡니다.
  3. 소스 설정에서 current: PLC_Simulation, twin: TwinForge를 확인합니다.
  4. Host 확인을 누르고 HTTP 응답을 확인합니다.

기대 결과

Host 응답 시각과 HTTP 코드가 표시됩니다. 소스 설정은 개별 조회 성공과 별개입니다.

문제가 생기면

  • 401이면 현재 실행의 Client key를 다시 확인합니다.
  • Host 응답이 없으면 로컬 서비스를 실행한 뒤 페이지를 다시 엽니다.

02

예시 질문을 확인하고 보내기

실행 확인

조회할 질문을 선택하고 입력 내용을 확인합니다.

  1. 현재 상태 예시 선택

    현재 선택한 설비 상태 어때?

  2. 질문과 글자 수 확인

    질문 확인·2,000자 이내

  3. 질문 전송

    Enter 또는 보내기

결과 확인

예시 질문과 글자 수가 함께 갱신됩니다. 줄바꿈은 Shift+Enter를 사용합니다.

한글 조합 중 Enter는 조합을 먼저 마칩니다. 이 실습은 설비 상태 조회입니다.

전체 조작 단계와 문제 해결

예시 질문과 입력

질문을 선택하고 전송 전에 내용을 확인합니다.

  1. 현재 선택한 설비 상태 어때? 예시 버튼을 누릅니다.
  2. 입력창의 질문과 글자 수를 확인합니다.
  3. 줄바꿈은 Shift+Enter, 전송은 Enter 또는 보내기를 사용합니다.

기대 결과

예시 질문이 입력되고 글자 수가 함께 갱신됩니다. 최대 입력은 2,000자입니다.

문제가 생기면

  • 한글 조합 중 Enter는 조합을 먼저 마칩니다.
  • 설비 제어 요청을 이 실습의 조회 기능으로 실행하지 않습니다.

03

선택 설비의 PLC 상태 조회

실행 확인

실제 PLC HTTP 소스로부터 조회한 답변을 읽습니다.

  1. PLC 실행 확인

    로컬 PLC Simulation 실행

  2. 현재 상태 질문 전송

    현재 상태 질문 → 보내기

  3. 응답 완료 대기

    역할·자산·키 변경 대기

  4. 답변과 오류 확인

    상태 답변 또는 조회 오류

결과 확인

PLC HTTP 소스의 조회 결과를 표시합니다. 이 판의 문장 생성 방식은 Fake입니다.

SOURCE_UNAVAILABLE은 소스 연결, ASSET_NOT_MAPPED는 선택 자산의 매핑을 확인합니다.

전체 조작 단계와 문제 해결

PLC 상태 조회

선택한 설비의 현재 상태를 실제 PLC HTTP 소스에서 읽습니다.

  1. PLC Simulation이 실행 중인지 확인합니다.
  2. 현재 상태 질문을 보내기를 눌러 전송합니다.
  3. 답변 대기 중에는 역할, 자산, 키 변경을 기다립니다.
  4. 응답 완료와 답변 내용을 확인합니다.

기대 결과

상태 답변 또는 구체적인 조회 오류가 표시됩니다. 이 판의 답변 생성 방식은 Fake입니다.

문제가 생기면

  • SOURCE_UNAVAILABLE이면 PLC 서비스와 주소를 확인합니다.
  • ASSET_NOT_MAPPED이면 선택 자산과 선언된 소스 매핑을 확인합니다.

04

답변의 출처·품질 검토

실행 확인

답변의 원본 시각과 생성 방식을 함께 확인합니다.

  1. 근거 영역 펼치기

    출처 · 품질 · 생성 방식 확인

  2. 출처와 인용 확인

    소유자·인용·생성 방식

  3. 품질과 시각 대조

    Good·최신 원본 시각

결과 확인

PLC_Simulation 출처·원본 시각·품질을 봅니다. Fake 생성 표시도 함께 확인합니다.

오래된 Good은 현재 값이 아닐 수 있습니다. Unknown·None·Unavailable은 사실 확인이 안 된 상태입니다.

전체 조작 단계와 문제 해결

출처와 품질 확인

답변의 근거와 생성 방식을 확인합니다.

  1. 답변 아래 출처 · 품질 · 생성 방식 확인을 펼칩니다.
  2. 생성 방식, 인용 여부, 소스 소유자와 원본 시각을 읽습니다.
  3. Good 품질과 최신 시각을 함께 확인합니다. Unknown이나 오류는 확인되지 않은 상태로 해석합니다.

기대 결과

PLC_Simulation 출처, 원본 시각, 품질과 Fake 생성 표시를 확인할 수 있습니다.

문제가 생기면

  • 오래된 Good 값은 현재 값으로 단정하지 않습니다.
  • 근거 None 또는 Unavailable이면 답변을 현재 설비 사실로 사용하지 않습니다.

05

답변과 근거를 함께 복사

실행 확인

검토한 답변을 출처와 시각까지 보존합니다.

  1. 답변 복사

    답변 복사

  2. 복사됨 확인

    버튼의 복사됨 표시

  3. 문서에 근거 보존

    소스·관측 시각 유지

결과 확인

답변 본문과 근거 메타데이터를 복사합니다. Client key는 포함하지 않습니다.

복사 실패가 표시되면 브라우저의 클립보드 접근 상태를 확인합니다.

전체 조작 단계와 문제 해결

답변과 근거 복사

근거를 포함한 답변을 복사합니다.

  1. 확인한 답변의 답변 복사 버튼을 누릅니다.
  2. 버튼이 복사됨으로 바뀌는지 확인합니다.
  3. 필요한 문서에 붙여 넣고 소스와 관측 시각을 함께 보존합니다.

기대 결과

답변 본문과 근거 메타데이터가 함께 복사됩니다. Client key는 포함하지 않습니다.

문제가 생기면

  • 복사 실패가 표시되면 브라우저의 클립보드 접근 상태를 확인합니다.

06

대화를 Markdown으로 저장

실행 확인

현재 질문·답변·근거를 파일로 보관합니다.

  1. 대화 내보내기

    대화 내보내기

  2. 다운로드 파일 열기

    다운로드한 .md 파일

  3. 기록과 근거 확인

    질문·답변·UTC 시각·근거

결과 확인

최대 100개 메시지를 Markdown으로 저장합니다. 키와 내부 세션 인증 정보는 제외합니다.

빈 대화에서는 비활성입니다. 파일이 없으면 브라우저 다운로드 알림과 차단 상태를 확인합니다.

전체 조작 단계와 문제 해결

대화 기록 내보내기

현재 대화를 Markdown 파일로 저장합니다.

  1. 질문과 답변이 있는 대화에서 대화 내보내기를 누릅니다.
  2. 다운로드된 industrial-assistant-날짜.md 파일을 엽니다.
  3. 질문, 답변, UTC 시각과 근거를 확인합니다.

기대 결과

최대 100개 메시지의 Markdown 기록을 저장합니다. 키와 내부 세션 인증 정보는 제외합니다.

문제가 생기면

  • 빈 대화에서는 내보내기 버튼이 비활성입니다.
  • 다운로드가 차단되면 이 로컬 페이지의 다운로드 알림을 확인합니다.

07

대화 맥락 비우고 새로 시작

실행 확인

이전 대화를 보관한 뒤 새 조회를 시작합니다.

  1. 보관할 대화 저장

    필요한 대화 먼저 내보내기

  2. 새 대화 시작

    새 대화 +

  3. 초기 상태 확인

    빈 목록·내보내기 비활성

결과 확인

‘새 대화를 시작했습니다’가 표시됩니다. 역할·자산을 변경할 때도 새 대화가 시작됩니다.

새 대화는 영구 기록·감사 원장 삭제가 아닙니다. 서버 대화는 세션·역할·자산별로 15분 유지됩니다.

전체 조작 단계와 문제 해결

새 대화 시작

이전 대화 맥락을 끊고 새 조회를 시작합니다.

  1. 보관할 대화가 있으면 먼저 내보냅니다.
  2. 새 대화 +를 누릅니다.
  3. 대화 목록이 비고 내보내기 버튼이 비활성인지 확인합니다.

기대 결과

새 대화를 시작했습니다가 표시됩니다. 역할이나 자산을 바꿀 때도 새 대화를 시작합니다.

문제가 생기면

  • 서버 대화는 세션, 역할, 자산별로 구분하며 메모리에서 15분 유지합니다.
  • 이 기능은 영구 대화 기록 삭제나 감사 원장 삭제 기능이 아닙니다.
