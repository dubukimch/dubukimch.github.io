IIoT Gateway

수집·품질·원본 시각·namespace·라우팅.NET · Blazor · OPC UA · Modbus

THE PROBLEM

해결하려는 과제

장치별 프로토콜과 주소 표현이 다르면 상위 서비스가 같은 연결 로직을 반복 구현하게 됩니다.

IMPLEMENTATION

구현한 작업 공간

Channel·Device·Tag 설정 계층과 OPC UA 정보 모델로 수집 경계를 제공합니다. UI에서는 연결·알람·이력·집계·시스템 설정을 탐색합니다.

  • Channel·Device·Tag 모델
  • Historian·Aggregation·Alarm 설정
  • OPC UA 정보 모델과 품질
  • 검증 콘솔과 역할 안내

DESIGN DECISIONS

설계 판단

  • 수집·품질·라우팅을 소유합니다.
  • OEE 계산과 자연어 설명은 다른 제품에 맡깁니다.
  • SmartFactorySim의 구형 OPC UA/Debug 참조를 MIT 버전으로 전환했습니다.
VERIFIED / 2026.10.05

확인된 동작

Docker ConfigUI와 역할 안내 경로 PASS. 채널 추가 폼을 브라우저에서 확인했습니다. SmartFactorySim MIT OPC UA 전환 후 빌드 오류 0.

NEXT ITERATION

추가 개선 범위

비명령 노드의 writable 기본값과 binding 없는 cache Write 경로를 점검하고 읽기 identity의 서버측 쓰기 거부를 검증해야 합니다.

내부 네트워크의 HTTP/WebSocket·MySQL 인증과 로컬 UI fixture를 검증했습니다. 실장비, 전체 6개 출처의 데이터 통합, 외부 AI 품질은 이번 검증 범위에 포함하지 않습니다.
