01

MES OPERATIONS

생산 계획부터 라인 실적까지 제어

MES Dashboard는 업종별 작업지시와 라인 스테이션을 생성하고, 생산 진행에 따른 Plan/Actual, WIP, OEE와 Scrap을 한 화면에서 보여줍니다.

UI CONTROL

운영자가 조작하는 항목

MES 업종 선택과 Start MES, Stop, Reset, Refresh로 생산 맥락을 제어합니다. 상단 공장 Start/Stop/Reset은 Gateway를 거쳐 PLC 명령·Ack 경로를 사용합니다.

IndustryStart MESStopResetRefreshPLC command
USER FLOW

사용 순서

  1. MES 영역에서 Automotive 업종을 선택합니다.
  2. Start MES로 작업지시와 라인 스테이션을 로드합니다.
  3. InProgress·Planned 상태와 현재 공정을 확인합니다.
  4. WIP·OEE·Scrap과 스테이션 부하를 보고 Stop 또는 Reset합니다.
WHAT HAPPENS

버튼 입력이 생산 KPI가 되는 과정

POST /api/mes/start선택 업종의 계획과 스테이션을 생성합니다.
MES 1초 Tick우선순위에 따라 최대 2개 작업을 진행합니다.
Status Snapshot수량·WIP·TPH·OEE를 계산해 3초 주기로 표시합니다.
  • 작업은 Planned → Released → InProgress → Completed로 이동합니다.
  • Body Weld는 Running, 후속 공정은 작업물 대기로 Starved를 표시합니다.
PORTFOLIO VALUE

차트만 배치한 대시보드가 아니라 사용자 제어, 작업 우선순위, 공정 상태 전이와 KPI 계산을 하나의 MES 도메인 흐름으로 구현했습니다.

02

EXTERNAL OEEANALYZER

MES 작업 맥락과 현장 근거를 한 패널에서 결합

External OEEAnalyzer 패널은 TwinForge가 제공한 작업지시·제품 맥락과 PLC → Gateway에서 수집한 생산 근거로 계산된 A/P/Q/OEE를 보여줍니다. coverage와 calculation status도 함께 표시해 결과를 사용할 수 있는지 판단하게 합니다.

UI CONTROL

운영자가 확인하고 실행하는 항목

연결 상태, Source Mode·calculation status, A/P/Q/OEE, coverage, Equipment·Work order·Product·Context ID와 Last sync를 확인하고 Sync now를 실행합니다.

Sync nowExternalA / P / QCoverageContext IDReasons
USER FLOW

사용 순서

  1. Automotive MES를 시작해 작업지시를 Released 또는 InProgress 상태로 만듭니다.
  2. 패널에서 OEEAnalyzer 연결과 선택 작업지시를 확인합니다.
  3. 자동 동기화를 기다리거나 Sync now를 눌러 즉시 갱신합니다.
  4. coverage, status와 reasons를 확인한 뒤 A/P/Q/OEE를 운영 판단에 사용합니다.
WHAT HAPPENS

작업지시가 분석 결과로 돌아오는 과정

Sample boundaryMES 시작 이후 수집된 Gateway 표본의 Source Timestamp를 production context 시작점으로 사용합니다.
Context upsert우선순위가 높은 활성 작업의 ID·제품·종료·ideal cycle을 OEEAnalyzer에 idempotent하게 저장합니다.
Window query현재 UTC까지의 최신 window를 조회해 패널 snapshot으로 반환합니다.
  • 백그라운드 서비스는 Docker 프로필에서 3초마다 동기화하고 화면은 5초마다 상태를 조회합니다.
  • Incomplete·AwaitingSamples에서는 충분한 Good 표본이 모일 때까지 OEE를 확정값으로 표시하지 않습니다.
IMPLEMENTED BOUNDARY

TwinForge의 내장 MES OEE와 External OEEAnalyzer 결과는 서로 평균하거나 합산하지 않습니다. 패널은 Source Mode, context ID와 calculation status를 노출해 두 계산 경로를 구분합니다.

03

LIVE EQUIPMENT

설비 상태와 센서 값을 실시간으로 추적

각 설비 카드는 상태, 위치와 장비별 속성을 보여줍니다. 외부 연동 프로필에서 MainConveyor 제어는 PLC Ack와 feedback으로 확정되고, 아직 매핑되지 않은 장비는 로컬 상태로 대체하지 않습니다.

UI CONTROL

운영자가 조작하는 항목

설비 카드별 Start·Stop, Telemetry 설비 선택, Alarm Severity·Equipment 필터와 전체 시뮬레이션 제어를 사용합니다.

Equipment StartEquipment StopTelemetry selectorSeverity filterEquipment filter
USER FLOW

사용 순서

  1. 업종을 선택하고 전체 시뮬레이션을 시작합니다.
  2. 설비 카드의 Running 상태와 최신 속성을 확인합니다.
  3. Telemetry 목록에서 추적할 설비를 선택합니다.
  4. 개별 Stop 또는 Start 후 상태·값·이력이 함께 바뀌는지 확인합니다.
WHAT HAPPENS

PLC 피드백이 브라우저에 도착하는 과정

OPC UA ingestionGood 품질의 RunFeedback·MachineState·SpeedPV를 수집합니다.
Ack validation명령 sequence와 Ack, 기대 feedback이 모두 일치해야 완료합니다.
SignalR + Store확정된 상태를 카드·이력·3D가 공유하는 Store에 반영합니다.
  • 최근 텔레메트리 20건과 최근 알람 100건을 유지합니다.
  • Bad 품질이나 timeout에서는 Running을 낙관적으로 표시하지 않습니다.
PORTFOLIO VALUE

Conveyor, Robot, AGV, Sensor처럼 속성이 다른 장비를 공통 상태 모델로 제어하면서 각 장비의 고유 텔레메트리를 유지합니다.

04

LOW-CODE WORKFLOW

제조 데이터 흐름을 배치하고 실행 상태를 검증

Workflow Designer에서 PLC, Data Mapping, Condition, Equipment와 Logger 노드를 연결하고 실행 순서, 상태와 로그를 시각적으로 검사합니다.

UI CONTROL

운영자가 조작하는 항목

New·Save·Copy·Delete, Run·Pause·Stop·Step, Import·Export와 Node Palette 드래그, 포트 연결, 속성 패널, 줌·미니맵을 사용합니다.

Drag & DropConnect portsRunPauseStepExport JSON
USER FLOW

사용 순서

  1. New 또는 기존 워크플로를 선택합니다.
  2. 노드를 캔버스에 끌어놓고 입출력 포트를 연결합니다.
  3. 노드 속성과 Enabled 상태를 설정하고 Save합니다.
  4. Run 후 WAITING → RUNNING → SUCCESS와 하단 로그를 확인합니다.
WHAT HAPPENS

현재 화면의 실행 시뮬레이션

연결 검증포트 타입 호환과 순환 참조를 검사합니다.
위상 정렬선행 노드부터 실행 순서를 계산합니다.
상태 시각화각 노드를 Running·Success로 바꾸고 로그를 추가합니다.
  • 5개 노드와 4개 연결이 모두 성공 상태로 표시됩니다.
  • 노드마다 시작·완료 로그가 남아 총 10건을 확인합니다.
IMPLEMENTED SCOPE

이 캡처의 Run은 브라우저 Store에서 동작하는 클라이언트 실행 시뮬레이션입니다. 연결 유효성과 실행 UX를 검증하며, 실제 PLC·OPC UA·Historian 호출이 수행된 것으로 과장하지 않습니다.

05

3D DIGITAL TWIN

공간에서 설비를 찾고 상태를 직접 제어

가상 공장은 설비 배치와 상태를 3D로 표현하면서 검색, 상태 필터, 카메라 시점, 선택 설비 상세와 Start/Stop 제어를 같은 작업 공간에 제공합니다.

UI CONTROL

운영자가 조작하는 항목

업종·시뮬레이션 제어, 설비 검색·상태 필터, 설비 목록과 3D 오브젝트 선택, 전체 조망·현장 시점·평면 보기, 선택 설비로 이동과 Start/Stop을 사용합니다.

IndustrySimulation StartSearchStatus filterCamera viewFocus assetAsset Start/Stop
USER FLOW

사용 순서

  1. 자동차 제조 업종을 선택하고 시뮬레이션을 시작합니다.
  2. 검색이나 상태 필터로 설비를 좁힙니다.
  3. 목록 또는 3D 오브젝트에서 MainConveyor를 선택합니다.
  4. 카메라를 이동하고 상세값을 확인한 뒤 설비 Start/Stop을 실행합니다.
WHAT HAPPENS

하나의 확정 상태가 2D와 3D에 함께 반영

PLC feedbackGood RunFeedback과 MachineState로 실제 설비 상태를 확정합니다.
Scene 동기화공통 Store의 상태로 Mesh 색상·라벨과 KPI를 다시 렌더링합니다.
Raycaster 선택오브젝트 ID로 오른쪽 상세와 제어 대상을 연결합니다.
  • 최신 캡처는 MainConveyor만 외부 PLC 매핑으로 가동되고 나머지는 대기 상태입니다.
  • 실시간 위치 변경은 카메라를 강제로 움직이지 않고 선택 설비 이동 때만 초점을 바꿉니다.
PORTFOLIO VALUE

3D를 장식으로 사용하지 않고 설비 검색, 운영 상태, 실시간 데이터, 카메라 탐색과 직접 제어를 연결한 현장 운영 UX입니다.
