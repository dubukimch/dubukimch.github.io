## 문제 분석

`TwinForge — External OEEAnalyzer 결과와 생산 맥락`을 포함한 일부 카드가 존재하지 않는 PNG 파일을 참조하고 있었다. 인덱스와 상세 페이지가 서로 다른 OEE 파일명을 사용한 것도 누락을 확산시켰다.

확인된 누락 참조는 다음과 같다.

- `oee-03-production-context.png`
- `oee-04-quality-diagnostics.png`
- `oee-05-processing-config.png`
- `oee-04-data-sources.png`
- `oee-05-processing-rules.png`

기존 설명과 캡처에는 과거 구현도 남아 있었다. 대표적으로 속도 단일 태그, 낙관적 MES 상태 변경, 6개 설비 전체 연동처럼 현재의 명령/Ack/피드백 경계와 맞지 않는 표현이 있었다.

## 반영한 아키텍처

- TwinForge는 `SpeedSetpoint`, `Command_Type`, `Command_Sequence`만 명령으로 기록한다.
- PLC Simulation은 `SpeedPV`, `RunFeedback`, `MachineState`, Ack와 생산 근거를 소유한다.
- IIoT Gateway는 명령 태그만 R/W, 상태·PV·Ack·생산 태그는 R로 노출한다.
- OEEAnalyzer는 `TotalCount`, `RejectCount`, `MachineState`, `CounterEpoch`를 읽고 결과를 계산한다.
- TwinForge는 명령 직후가 아니라 PLC Ack와 피드백을 기준으로 화면 상태를 갱신한다.
- 현재 External 프로필에서 실제 OPC UA 설비 매핑은 `MainConveyor`이며, 나머지 설비는 미매핑 대기 상태로 표시한다.

## 수정 내용

### 이미지 참조

- 인덱스의 오래된 OEE 파일명을 상세 페이지와 같은 `oee-04-data-sources.png`, `oee-05-processing-rules.png`로 통일했다.
- 새로 생성하거나 갱신한 이미지 URL에 `?v=20260916`을 붙여 배포 후 브라우저 캐시가 이전 이미지를 재사용하지 않게 했다.
- OEE Data Sources 캡션을 실제 캡처 범위인 endpoint와 4개 생산 업무 노드 중심으로 정리했다.

### 최신 화면 캡처

실행 중인 4개 제품을 연결한 뒤 다음 10개 이미지를 다시 생성했다.

- PLC Simulation: `plc-04-live-tags.png`
- IIoT Gateway: `gateway-03-tags.png`
- TwinForge: `twin-01-mes-dashboard.png`, `twin-04-3d-factory.png`, `twin-04-3d.png`
- TwinForge External OEE: `oee-03-production-context.png`
- OEEAnalyzer: `oee-01-integration-overview.png`, `oee-02-live-oee.png`, `oee-04-data-sources.png`, `oee-05-processing-rules.png`

최종 OEE 캡처는 Final window, 100% coverage, A/P/Q/OEE, 생산량, context ID와 revision이 보이는 정상 상태를 사용했다. Data Sources에는 실제 Gateway endpoint와 4개 업무 태그를 저장하고, Processing Rules에는 Total/Reject/State와 ideal cycle 매핑을 표시했다.

### 포트폴리오 설명

- 메인 페이지의 시스템 수와 화면 수를 4개 제품, 20개 화면으로 갱신했다.
- PLC, Gateway, TwinForge, OEEAnalyzer 및 기술 문서의 설명을 명령 쓰기와 상태 읽기의 소유권 경계에 맞췄다.
- TwinForge의 MES/3D 설명에서 로컬 낙관 상태와 전체 설비 매핑 표현을 제거하고 실제 Ack·피드백 동작을 반영했다.

### 재현 가능한 캡처

`scripts/capture-industrial-portfolio.mjs`를 추가했다. 이 스크립트는 다음을 자동으로 확인한다.

1. PLC 태그 모니터와 Gateway 14개 태그 화면 로드
2. Automotive MES reset/start
3. External OEE의 Performance·Quality·OEE가 계산될 때까지 재동기화
4. 완료 지연 정책을 지난 Final OEE 구간 조회
5. Data Sources의 실제 endpoint 및 4개 태그 구성
6. Processing Rules의 Total/Reject/State 매핑

OEE 비밀번호는 파일에 저장하지 않고 실행 시 `PORTFOLIO_OEE_PASSWORD` 환경 변수로만 전달한다.
