01

5-SYSTEM INTEGRATION

연결 상태와 분석 결과를 한 화면에서 확인

PLC Simulation, IIoT Gateway, TwinForge, OEEAnalyzer와 DataNexus의 경로를 설비 키 하나로 연결합니다. 실시간 표본과 기간 분석을 섞지 않고 각각의 출처와 시각을 보존합니다.

WHAT THE UI SHOWS

운영 판단에 필요한 핵심 증거

시스템별 연결 상태, Availability·Performance·Quality·OEE, coverage, 분석 status와 revision을 표시합니다. Kafka 표본에서는 machine state, total/reject count, quality와 source timestamp를 별도로 확인합니다.

equipmentKeyA/P/Q/OEEcoveragequalitypartition/offsetrevision
CAPTURED RESULT

실행 화면의 검증 값

  1. 다섯 시스템의 연결 상태가 모두 Connected로 표시됐습니다.
  2. Kafka 표본 품질은 Good, 설비 상태는 Running이었습니다.
  3. OEE Window coverage는 100%였습니다.
  4. 캡처 시점에 71건 소비, 0건 거부를 확인했습니다.
IMPLEMENTATION

읽기 전용 통합이 동작하는 방식

Kafka consumer독립 consumer group으로 OEE v1 표본을 읽고 key·payload 설비 키와 schema를 검증합니다.
OEE REST readerJWT service login 후 동일한 설비와 기간의 권위 있는 OEE Window를 조회합니다.
Unified snapshot원본 시각·수신 시각·quality·offset·revision을 보존해 UI와 상태 API에 제공합니다.
  • 합성 uptime이나 클라이언트 OEE 재계산을 사용하지 않습니다.
  • 잘못된 payload는 commit 전 전용 DLQ로 분리합니다.
DESIGN BOUNDARY

DataNexus는 PLC 쓰기와 생산 제어 경로에 참여하지 않습니다. 실시간 Kafka 표본은 현장 상태의 증거이고, KPI 수치는 OEEAnalyzer 결과를 그대로 사용합니다.

02

MES PRODUCTION CONTEXT

TwinForge의 작업 맥락과 External OEE를 연결

TwinForge가 작업지시, 제품과 계획 구간을 OEEAnalyzer에 제공하고, 계산된 External 결과를 다시 조회하는 경계를 실제 운영 화면으로 확인했습니다.

BUSINESS CONTEXT

계측값에 업무 의미를 추가

MO-A1001 작업지시와 EDU-400 제품, 계획 구간과 ideal cycle을 설비 키에 연결합니다. OEEAnalyzer는 이 맥락을 생산 표본의 기간 계산 경계로 사용합니다.

RESULT CONTRACT

자체 Demo OEE와 외부 결과 분리

External 모드에서는 Analyzer 결과를 TwinForge 자체 지표와 평균하거나 합산하지 않습니다. 설비·기간·context·revision이 맞는 결과만 별도 패널에 표시합니다.

03

AUTHORITATIVE OEE WINDOW

수치와 함께 coverage·상태·revision을 보존

OEEAnalyzer를 A/P/Q/OEE의 단일 계산 주체로 유지합니다. DataNexus는 계산 결과를 바꾸지 않고 진단 정보와 함께 제시해 재현 가능한 비교 기준을 만듭니다.

CAPTURED RESULT

독립 화면에서 확인한 계산값

캡처된 Final Window는 Availability 100.0%, Performance 88.7%, Quality 96.4%, OEE 85.5%, coverage 100.0%와 revision 345를 표시했습니다.

TIME-AWARE COMPARISON

캡처 시점이 다르면 revision도 다릅니다

생산 이벤트가 계속 유입되는 동안 Window가 재계산되므로 화면별 수치가 달라질 수 있습니다. 비교할 때는 equipmentKey, contextId, UTC 구간과 revision을 함께 사용합니다.

04

DOCKER ACCEPTANCE

화면이 아니라 전체 데이터 경로를 자동 검증

단일 Docker Compose 환경에서 PLC 신호부터 Gateway 품질, TwinForge 제어 Ack, OEE 계산과 DataNexus 소비 상태까지 순서대로 검사했습니다.
