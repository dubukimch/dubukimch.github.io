BEFORE YOU START

시작하기 전에

  • Workbench를 활성화한 로컬 Host가 실행 중이어야 합니다.
  • 실습 예제는 원본 설비와 분리된 모의 초안으로 등록합니다.

local-workbench / fixture-lab의 모의 초안과 로컬 의미 연결. 운영 승인, AAS 게시, 실제 설비 제어는 제공하지 않습니다.

01

온톨로지 작업공간 둘러보기

실행 확인

자산 초안, 의미 연결, 개념 사전의 위치를 파악합니다.

  1. 스튜디오 열기

    온톨로지 스튜디오

  2. 자산과 연결 확인

    초안 목록·의미 연결

  3. 공통 개념 사전 읽기

    공통 개념 사전·로컬 검토 안내

결과 확인

초안 수와 연결 진행률이 표시됩니다. 기존 예제가 있으면 첫 자산을 선택합니다.

현재는 로컬 검토 환경입니다. 404이면 Workbench 활성화 프로필과 주소를 확인합니다.

전체 조작 단계와 문제 해결

온톨로지 스튜디오 확인

초안, 의미 연결, 개념 사전의 위치를 파악합니다.

  1. 온톨로지 스튜디오를 엽니다.
  2. 연결할 자산 목록과 의미 연결 작업공간을 확인합니다.
  3. 공통 개념 사전과 로컬 검토 환경 안내를 확인합니다.

기대 결과

초안 수와 연결 진행률이 표시됩니다. 기존 예제가 있으면 첫 자산을 선택합니다.

문제가 생기면

  • 404이면 Workbench 활성화 프로필과 로컬 주소를 확인합니다.

02

교육용 자산의 원본 선언

실행 확인

자산 이름과 소스 범위를 초안에 입력합니다.

  1. 새 자산 초안 열기

    새 자산 초안

  2. 이름과 소유자 입력

    매뉴얼 예제 온도·Gateway

  3. 원본 소스 범위 지정

    Simulation·manual-local

  4. 유효 시간과 메모 확인

    유효 시작 UTC·모의 예제 메모

결과 확인

자산명과 소스 범위가 입력 창에 표시됩니다. 키: DataAccess.Manual.Temp_PV

이것은 소스 선언입니다. 입력만으로 원본 연결이 생기지 않으며 취소·닫기로 등록 전 취소할 수 있습니다.

전체 조작 단계와 문제 해결

모의 자산 초안 입력

새 자산의 소스 정보를 선언합니다.

  1. 새 자산 초안을 누릅니다.
  2. 자산명은 매뉴얼 예제 온도, 소스 소유자는 Gateway로 입력합니다.
  3. 원본 모드 Simulation, 소스 인스턴스 manual-local, 원본 소스 키 DataAccess.Manual.Temp_PV를 입력합니다.
  4. 유효 시작 UTC와 모의 예제라는 메모를 확인합니다.

기대 결과

입력 창에 자산명, 소유자, 소스 범위가 표시됩니다. 입력만으로 원본 연결이 생성되지 않습니다.

문제가 생기면

  • 등록을 취소하려면 취소나 닫기를 누릅니다.
  • 시간은 UTC로 입력하고 종료는 시작보다 뒤로 지정합니다.

03

초안 저장과 식별자 확인

실행 확인

로컬 초안을 저장하고 고유 ID와 편집 버전을 읽습니다.

  1. 초안 만들기

    입력 확인 → 초안 만들기

  2. 새 자산 행 확인

    새 행·선택한 자산 상세

  3. ID와 버전 읽기

    Global Asset ID·편집 버전

결과 확인

초안과 발급된 식별자가 로컬 파일에 저장됩니다. 승인·게시 revision은 미제공 상태입니다.

오래된 편집의 412 응답은 최신 초안과 비교합니다. 같은 저장 경로를 여러 Host가 동시에 열지 않습니다.

전체 조작 단계와 문제 해결

초안 저장과 식별자 확인

초안을 저장하고 발급된 ID를 확인합니다.

  1. 입력값을 확인한 뒤 초안 만들기를 누릅니다.
  2. 자산 작업공간의 새 행과 선택한 자산 상세를 확인합니다.
  3. Global Asset ID와 편집 버전을 확인합니다.

기대 결과

초안과 식별자를 로컬 파일에 저장합니다. 승인 및 게시 revision은 미제공으로 남습니다.

문제가 생기면

  • 오래된 편집의 412 응답은 최신 초안을 다시 읽고 변경 내용을 비교합니다.
  • 같은 저장 경로를 여러 Host가 동시에 열지 않습니다.

04

온도 개념 후보 검토

실행 확인

이름·소스 키의 일치 근거를 보고 개념을 선택합니다.

  1. 교육용 자산 선택

    매뉴얼 예제 온도

  2. 후보와 일치 근거 읽기

    자동 매칭 후보·온도 근거

  3. 개념 후보 반영

    선택 → 의미 개념 반영

  4. 단위와 위치 직접 입력

    원 단위·계측 위치 입력

결과 확인

선택한 개념이 의미 연결 폼에 반영됩니다. 후보 점수는 문자열 일치 순위입니다.

점수는 승인 확률이 아닙니다. 이름만 같다고 다른 계측 지점을 같은 자산으로 병합하지 않습니다.

전체 조작 단계와 문제 해결

개념 후보 선택

이름과 소스 키의 문자열 근거를 검토합니다.

  1. 온톨로지 스튜디오에서 매뉴얼 예제 온도를 선택합니다.
  2. 자동 매칭 후보의 온도와 일치 근거를 읽습니다.
  3. 선택을 눌러 개념을 채우고 원 단위와 계측 위치를 직접 입력합니다.

기대 결과

선택한 개념이 의미 연결 폼에 반영됩니다. 점수는 문자열 순위이며 승인 확률이 아닙니다.

문제가 생기면

  • 후보가 없으면 개념 사전에서 직접 고릅니다.
  • 이름 일치만으로 서로 다른 계측 지점을 같은 자산으로 병합하지 않습니다.

05

개념·단위·계측 위치 연결

실행 확인

계측 지점의 의미와 단위를 함께 저장합니다.

  1. 클래스와 개념 지정

    계측 지점·온도

  2. 단위와 위치 입력

    °C·실습 모의 계측 지점

  3. 의미 연결 저장

    의미 연결 저장

  4. 저장된 관계 확인

    observes·편집 버전

결과 확인

의미 연결과 편집 버전이 저장됩니다. 기존 로컬 검토 결과는 무효화됩니다.

라인·설비에는 계측 필드를 비웁니다. 미지원 단위나 순환 partOf 관계는 거부됩니다.

전체 조작 단계와 문제 해결

의미 연결 저장

계측 지점의 개념, 단위와 위치를 저장합니다.

  1. 클래스는 계측 지점, 의미 개념은 온도로 둡니다.
  2. 원 단위 °C, 계측 위치는 실습 모의 계측 지점으로 입력합니다.
  3. 의미 연결 저장을 누르고 저장된 observes 관계를 확인합니다.

기대 결과

의미 연결과 편집 버전을 저장하며 기존 로컬 검토를 무효화합니다.

문제가 생기면

  • 라인과 설비에는 계측 필드를 비웁니다.
  • 지원하지 않는 단위나 순환 partOf 관계는 서버가 거부합니다.

06

키워드로 의미 연결 근거 찾기

실행 확인

로컬 초안에 선언한 자산과 소스를 검색합니다.

  1. 키워드 입력

    온톨로지 어시스트: 매뉴얼 온도

  2. 근거 조회

    근거 조회

  3. 선언 근거 대조

    자산·개념·소스 tuple·버전

결과 확인

로컬 초안 snapshot의 선언 근거를 보여줍니다. 실제 값·품질·원본 시각은 미제공입니다.

규칙 기반 검색이며 외부 AI를 호출하지 않습니다. 결과가 없으면 키워드를 줄이고 의미 연결 저장을 확인합니다.

전체 조작 단계와 문제 해결

의미 연결 근거 조회

키워드로 자산과 원본 소스 선언을 찾습니다.

  1. 온톨로지 어시스트에 매뉴얼 온도를 입력합니다.
  2. 근거 조회를 누릅니다.
  3. 자산, 개념, 위치, 소스 tuple과 편집 버전을 함께 확인합니다.

기대 결과

로컬 초안 snapshot의 근거를 표시합니다. 실제 값, 품질과 원본 시각은 미제공입니다.

문제가 생기면

  • 검색 결과가 없으면 키워드를 줄이고 먼저 의미 연결을 저장합니다.
  • 이 어시스트는 규칙 기반 검색이며 외부 AI를 호출하지 않습니다.

07

Host 상태와 운영 준비 구분

실행 확인

실행 상태와 운영에 필요한 준비 항목을 따로 읽습니다.

  1. 시스템 모니터링 열기

    시스템 모니터링

  2. 상태 새로고침

    상태 새로고침

  3. 관측값과 준비 항목 읽기

    메모리·가동 시간·체크리스트

결과 확인

Host 실행과 서비스 준비 상태가 따로 보입니다. 운영 원장·인증·표준 runtime은 준비 중입니다.

상태 요청에 실패하면 최근 성공값을 현재 관측값으로 해석하지 않습니다.

전체 조작 단계와 문제 해결

Host 상태와 준비 상태 확인

실행 중인 Host와 운영 준비 상태를 구분합니다.

  1. 시스템 모니터링을 엽니다.
  2. 상태 새로고침을 누릅니다.
  3. 메모리, 가동 시간과 관측 시각을 확인하고 준비 상태 체크리스트를 읽습니다.

기대 결과

Host 실행과 서비스 미준비를 별도로 표시합니다. 현재 운영 원장, 인증과 표준 runtime은 준비 중입니다.

문제가 생기면

  • 상태 요청 실패 시 최근 성공값을 현재 관측으로 해석하지 않습니다.

08

일곱 솔루션의 HTTP 상태 확인

실행 확인

로컬 작업공간으로 이동하며 응답 근거를 확인합니다.

  1. 솔루션 연결 열기

    솔루션 연결

  2. 연결 상태 확인

    연결 상태 확인

  3. 응답과 관측 시각 읽기

    HTTP·지연·UTC 관측 시각

  4. 작업공간으로 이동

    작업공간 열기

결과 확인

고정된 loopback 경로를 최대 2초씩 조회합니다. 현재 Gateway·OEE API는 응답 없음입니다.

HTTP 응답은 데이터 전송·운영 승인 증거가 아닙니다. UI 접근과 backend 수집 상태를 따로 확인합니다.

전체 조작 단계와 문제 해결

일곱 솔루션 연결 상태 확인

로컬 솔루션으로 이동하고 HTTP 응답을 확인합니다.

  1. 솔루션 연결을 엽니다.
  2. 연결 상태 확인을 누릅니다.
  3. HTTP 응답 코드, 지연과 UTC 관측 시각을 읽고 작업공간 열기로 이동합니다.

기대 결과

고정된 loopback 경로를 최대 2초씩 조회합니다. HTTP 응답만으로 데이터 전송이나 운영 승인을 입증하지 않습니다.

문제가 생기면

  • Gateway와 OEE API가 중지된 현재 환경에서는 응답 없음이 정상 진단입니다.
  • 각 UI가 열리는지와 해당 backend의 수집 상태를 별도로 확인합니다.
