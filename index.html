CONTROL BOUNDARY

Command / Feedback

SpeedSetpoint·CommandType·CommandSequence만 쓰고, Ack·RunFeedback·MachineState·SpeedPV를 확인해 결과를 확정합니다.

OEE ANALYTICS CONTRACT

Count · state · context

Total, Reject, State, Counter Epoch를 Kafka로 보존하고 TwinForge의 작업·제품·계획 구간·ideal cycle을 기간 계산에 결합합니다.

INDEPENDENT OBSERVER

Evidence · Window · lineage

DataNexus는 제어하거나 다시 계산하지 않습니다. 독립 Kafka group과 읽기 전용 OEE API로 실시간 근거와 권위 결과를 대조합니다.

QUALITY-AWARE RESULT

Coverage · reasons · revision

결측 구간은 정상값으로 채우지 않습니다. 결과와 함께 coverage, Provisional·Incomplete·Final 상태, 원인과 revision을 반환합니다.

ENGINEERING PRINCIPLES

연결보다 중요한 것은
신뢰할 수 있는 흐름입니다.

다섯 프로젝트에서 반복해 적용한 설계 기준입니다. 장비 연결 자체보다 데이터의 품질, 추적 가능성, 안전한 제어와 재현 가능한 검증을 제품의 기준으로 삼았습니다.

01 / MODEL

Protocol first

장비별 차이를 OPC UA 정보 모델로 흡수하고, 클라이언트가 일관된 태그와 상태를 사용하도록 설계합니다.

02 / OBSERVE

Observable by default

연결 상태, 품질 코드, 현재 값과 이벤트 이력을 화면에서 즉시 판단할 수 있게 노출합니다.

03 / CONTROL

Safe by design

쓰기 경로와 알람 수명주기를 분리해 제어 결과와 이상 상태를 명확하게 확인할 수 있도록 구성합니다.

04 / VERIFY

Reproducible demo

Docker와 가상 PLC 데이터로 동일한 시나리오를 반복 실행하고 결과를 화면과 로그로 검증합니다.
