DEVICE CONNECTIVITY · USER WALKTHROUGH

PLC를 고르고,값을 직접 제어합니다.

운영자는 제조사별 드라이버와 PLC 모델을 선택하고 접속 정보를 설정한 뒤, 실시간 태그를 읽거나 쓰고 상위 시스템용 표준 경로까지 관리할 수 있습니다. 아래 다섯 화면은 그 작업 순서를 실제 UI 기준으로 설명합니다.

01

OPERATIONS OVERVIEW

드라이버 상태와 통신 로그를 한눈에

Dashboard는 시작 직후 시스템이 어떤 드라이버를 불러왔고, 무엇이 연결되어 있으며, 태그 통신이 정상인지 판단하는 운영 시작점입니다.

UI CONTROL

운영자가 사용하는 항목

Manage는 Driver Configuration으로, Open Logs는 전체 로그 화면으로 이동합니다. WS Online과 카드의 스위치 모양은 이 화면에서 상태를 읽기 위한 표시입니다.

ManageOpen LogsWS OnlineDriver statusDashboard menu
USER FLOW

사용 순서

  1. Dashboard에서 Loaded Drivers와 Connected 수를 확인합니다.
  2. Driver Health에서 연결·비활성 드라이버를 구분합니다.
  3. 설정 변경이 필요하면 Manage로 이동합니다.
  4. Live Communication Log에서 TX·RX·SYS 요청과 응답을 확인합니다.
WHAT HAPPENS

구성 변경이 대시보드에 반영되는 과정

Driver 설정 저장Configuration 화면에서 활성 상태와 접속값을 저장합니다.
DriverHost 재구성드라이버를 연결하고 태그를 검색·폴링합니다.
WebSocket 갱신상태·카운트·통신 로그를 Dashboard에 전송합니다.
  • 캡처에서 MQTT·FINS·Modbus·S7의 4개 연결을 확인합니다.
  • 한 드라이버가 실패해도 나머지 폴링은 계속됩니다.
PORTFOLIO VALUE

단순 상태 카드가 아니라 드라이버 활성화, 연결 복구, 태그 탐색과 로그 관찰을 하나의 운영 화면에 묶은 장애 진단 UX입니다.

02

DRIVER CATALOG

제조사와 프로토콜을 같은 방식으로 탐색

PLC Nodes 화면은 플러그인 DLL에서 읽은 제조사, 프로토콜, 연결 주소와 태그 규모를 카드로 보여줍니다. 새 드라이버가 추가돼도 UI 구조는 그대로 유지됩니다.

UI CONTROL

화면에서 확인하는 정보

각 카드의 상태 배지, Endpoint, Vendor, Tags와 활동 표시를 비교해 구성할 드라이버를 고릅니다. 활동 표시는 연결·태그 상태를 요약하며 실측 성능 지표가 아닙니다.

Status badgeEndpointVendorTag countActivity
USER FLOW

사용 순서

  1. 사이드바의 PLC Nodes를 선택합니다.
  2. 프로토콜 또는 제조사 카드의 Endpoint를 확인합니다.
  3. 상태 배지와 태그 수로 현재 사용 가능 여부를 판단합니다.
  4. 구성이 필요하면 Driver Configuration으로 이동합니다.
WHAT HAPPENS

카탈로그가 만들어지는 방식

DLL 탐색IPlcDriver 구현과 메타데이터를 찾습니다.
공통 모델 변환Vendor·Protocol·Endpoint·Tags로 정규화합니다.
카드 렌더링서로 다른 프로토콜을 동일한 UI로 표시합니다.
  • 통신 방식이 달라도 운영자는 같은 탐색 절차를 사용합니다.
  • 플러그인 추가가 화면 코드 변경으로 이어지지 않습니다.
PORTFOLIO VALUE

Modbus TCP, MELSEC, FINS, S7, MQTT 등 이기종 프로토콜을 공통 드라이버 계약과 하나의 웹 UX로 추상화했습니다.

03

MODEL + CONNECTION

PLC 모델을 선택하고 연결값을 적용

운영자는 Protocol Profile, PLC Model, Communication Module을 선택해 기본값을 불러온 뒤 호스트·포트·Station 등 실제 접속값을 조정합니다.

UI CONTROL

운영자가 입력하는 값

프로토콜·모델·통신 모듈 드롭다운, Apply to Driver, DLL 업로드, 활성 스위치와 Endpoint·Listen Host·Port·Station 필드를 사용합니다.

Protocol ProfilePLC ModelCommunication ModuleApply to DriverUpload DLL
USER FLOW

사용 순서

  1. 왼쪽 Plugin Manager에서 대상 드라이버를 선택합니다.
  2. 프로토콜, PLC 모델과 통신 모듈을 선택합니다.
  3. Apply to Driver로 추천 기본값을 폼에 반영합니다.
  4. 현장 환경에 맞게 호스트·포트·Station을 수정하고 활성화합니다.
WHAT HAPPENS

적용 버튼 이후의 처리

프로파일 병합프로토콜·모델·모듈 기본값과 현재 입력을 합칩니다.
ConfigureAsync캐시를 비우고 드라이버 연결 정보를 갱신합니다.
재연결·태그 검색활성 드라이버를 다시 연결하고 태그를 발견합니다.
  • 선택한 모델에 맞는 통신 기본값이 반복 입력을 줄입니다.
  • 저장된 구성은 다음 실행 때 다시 복원됩니다.
PORTFOLIO VALUE

장비 전문가가 아니어도 모델 카탈로그를 기준으로 설정할 수 있고, 필요하면 DLL 플러그인을 추가해 통신 범위를 확장할 수 있습니다.

04

LIVE READ + WRITE

실시간 값을 보고, 쓰고, 결과를 확인

Tag Monitor는 태그 주소, 데이터 형식, 현재 값, 품질과 갱신 시각을 보여주며 쓰기 가능한 태그에는 Write 동작을 제공합니다.

UI CONTROL

운영자가 조작하는 항목

Tag Explorer에서 드라이버를 고르고 Refresh로 스냅샷을 요청합니다. R/W 태그의 Write 버튼을 눌러 새 값을 입력합니다.

Tag ExplorerRefreshWriteValue inputQuality badge
USER FLOW

검증한 쓰기 순서

  1. Modbus TCP Device Simulator를 선택합니다.
  2. Speed_SP 행의 Write를 누르고 1800을 입력합니다.
  3. 완료 알림과 GOOD 품질을 확인합니다.
  4. 다음 실시간 스냅샷에서 변경된 값을 확인합니다.
WHAT HAPPENS

입력값이 화면에 돌아오기까지

POST /api/tags/write태그 ID·주소와 입력 문자열을 전달합니다.
프로토콜 쓰기형식과 바이트 순서에 맞춰 PLC 프레임으로 변환합니다.
캐시 + WebSocket성공 값을 GOOD 품질로 저장하고 화면에 재전송합니다.
  • 화면에서 입력한 값이 PLC 메모리까지 전달됩니다.
  • 품질과 갱신 시각으로 성공 여부를 즉시 판별합니다.
PORTFOLIO VALUE

정적 데모가 아니라 실제 프로토콜 Read/Write, 데이터 형식 변환, 최신 값 캐시와 WebSocket UI 갱신을 하나의 사용자 동작으로 검증했습니다.

05

SEMANTIC MAPPING

PLC 주소를 상위 시스템용 경로로 변환

Data Mapping은 40001, D100처럼 프로토콜에 종속된 주소를 MES와 Gateway가 읽을 수 있는 표준 경로와 별칭으로 관리합니다.

UI CONTROL

운영자가 조작하는 항목

Sync Tags, 검색창과 드라이버 필터로 대상을 찾고 Alias·표준 경로·활성 상태를 편집한 뒤 행별 Save 또는 Delete를 실행합니다.

Sync TagsSearchDriver filterAliasStandard pathExport CSV
USER FLOW

사용 순서

  1. Sync Tags로 현재 드라이버의 태그를 불러옵니다.
  2. Missing 지표와 필터로 미매핑 항목을 찾습니다.
  3. 업무용 Alias와 표준 경로를 입력하고 활성화합니다.
  4. Save로 저장하거나 Export CSV로 검토 자료를 만듭니다.
WHAT HAPPENS

매핑이 상위 시스템에 주는 효과

원본 태그 발견프로토콜 주소와 데이터 형식을 수집합니다.
표준 경로 저장별칭·경로·활성 상태를 Mapping Store에 기록합니다.
상위 시스템 사용주소 체계를 몰라도 동일한 의미 경로로 조회합니다.
  • 누락 매핑 수가 즉시 집계되어 배포 전 오류를 찾습니다.
  • CSV로 내보내 현장 태그 목록을 리뷰할 수 있습니다.
PORTFOLIO VALUE

프로토콜 연결에서 끝나지 않고, 물리 주소를 업무 의미가 있는 데이터 계약으로 바꾸는 통합 경계를 구현했습니다.
